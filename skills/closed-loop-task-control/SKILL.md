# Closed-loop Task Control

## 目标

避免“做了很多，但没有真正完成”。

## 执行步骤

1. **目标**：最终交付什么；
2. **输入**：已有资料和前提；
3. **责任人**：谁做、谁确认、谁审批；
4. **动作**：具体要完成哪些步骤；
5. **关键节点**：什么时候必须反馈；
6. **验收标准**：什么叫完成；
7. **异常处理**：失败或信息缺失时怎么升级；
8. **闭环证据**：报告、波形、记录、签字、版本号或确认消息；
9. **复盘**：哪些规则值得沉淀成下一次默认流程。

## 测试任务最小闭环

测试对象 → 工况 → 测量量 → 仪器/采样 → 操作步骤 → 判据 → 异常条件 → 原始数据 → 结论 → 归档。

## 供应商任务最小闭环

问题 → 背景工况 → 明确问题 → 要求资料/数据 → 截止时间 → 回复 → 核验 → 是否满足 → 下一步。

## 多 Agent 场景

每个 Agent 都必须有：
- 明确输入；
- 明确输出；
- 验收标准；
- 失败时的升级路径。

不要只写“研究一下”“优化一下”“看看有没有问题”。

## 输出

优先输出一个可执行任务定义，而不是泛泛建议。
