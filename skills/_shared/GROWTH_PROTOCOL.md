# Skill Growth Protocol

本协议适用于本仓库当前和未来的所有 Skill。目标不是让 Skill “自动漂移”，而是让它在真实使用中形成可审计、可回滚、可验证的持续改进闭环。

## 核心原则

1. **先完成任务，再学习**：不能为了收集经验牺牲当前任务质量。
2. **经验不等于规则**：单个案例只能成为候选经验，不能直接改成通用规则。
3. **事实、偏好、方法分开**：个人偏好只影响个性化，不自动升级为通用方法。
4. **证据优先于印象**：用户纠正、权威资料、重复失败、成功复现的权重高于“感觉这样更好”。
5. **不自动削弱边界**：任何成长都不能绕过安全、法律、隐私和专业边界。
6. **公开仓库不存敏感信息**：真实个人资料、公司内部信息、健康/财务等敏感案例只记在本地私有日志。
7. **所有升级都必须可回滚**：正式修改 Skill 前保留变更原因、测试案例和版本记录。

## 每次使用后的成长闭环

完成主任务后，内部执行以下检查。没有值得记录的新信息就结束，不为了“成长”制造记录。

### 1. Capture — 捕获

检查本次任务是否出现以下信号：

- 用户明确指出答案错误、遗漏或不符合真实场景；
- Skill 的步骤无法覆盖任务，必须临时绕路；
- 某一步反复产生低价值输出；
- 新增了稳定、可迁移的方法；
- 某个边界条件导致原规则失效；
- 新的一手资料推翻或更新旧规则；
- 同一类任务连续出现相同问题；
- 某种输出结构显著提高了执行效率或正确率。

记录时只写“可学习内容”，不要复制整段聊天。

### 2. Classify — 分类

每条成长候选归到一种类型：

- `FACT_UPDATE`：外部事实、标准、政策、数据更新；
- `METHOD`：更好的分析/执行步骤；
- `EDGE_CASE`：边界条件、例外情况；
- `FAILURE`：Skill 失败模式；
- `OUTPUT`：更好的交付结构；
- `PERSONAL`：只对当前用户成立的偏好或约束；
- `SCOPE`：触发条件或禁用条件需要调整。

其中 `PERSONAL` 默认只进入本地私有上下文，不进入公共 Skill。

### 3. Grade — 给候选经验分级

使用四级成熟度，而不是看到一次就修改 Skill：

- **G0 Observation**：只出现一次，尚未验证。
- **G1 Candidate**：有合理依据，或用户明确纠正过一次。
- **G2 Validated**：满足以下任一条件：
  - 至少 2 个独立真实案例重复出现；
  - 有权威/一手资料直接支持；
  - 用户明确纠正且可由外部事实核实；
  - 回归测试能稳定证明新方法优于旧方法。
- **G3 Promote**：已经验证，并且适用于未来同类任务，加入 Skill 的收益大于复杂度和冲突成本。

只有 G3 才进入正式 Skill。

## 升级门槛

以下情况可以直接进入“待升级评审”，但仍需测试：

- 安全性或事实性错误；
- 明确违反标准/法规/接口契约；
- 原规则会稳定导致错误决策；
- 上游依赖发生确定性变化。

以下情况不得仅凭一次案例写入通用 Skill：

- 用户个人偏好；
- 单一公司的特殊流程；
- 某个项目一次性的临时约束；
- 无法核实的经验之谈；
- 为迎合一次回答风格而改变方法论。

## Promote — 正式成长

准备升级 Skill 时：

1. 写清旧行为的问题；
2. 写清新规则解决什么；
3. 标注证据来源或真实案例编号；
4. 新增至少：
   - 1 个正例；
   - 1 个边界例；
   - 1 个反例/不应触发例；
5. 检查是否与其他 Skill 冲突；
6. 优先修改共享协议或上层路由，避免在多个 Skill 复制同一规则；
7. 通过分支 + PR 修改，不直接写 `main`；
8. 合并后记录版本和变更原因。

## Regression — 回归测试

每个成熟 Skill 应逐步维护一个最小回归集，重点验证：

- 正确触发；
- 不该触发时不会误触发；
- 核心步骤没有被删掉；
- 旧的高质量案例仍能得到合理结果；
- 新增规则确实修复目标问题；
- 没有引入新的隐私、安全或事实性风险。

回归案例应尽量使用脱敏、抽象后的情景。

## Growth Log

如果本地存在 `personal/SKILL_GROWTH_LOG.md`，将成长候选追加到该文件。

推荐格式：

```markdown
## YYYY-MM-DD — <skill-name>
- 类型：
- 成熟度：G0/G1/G2/G3
- 触发场景：
- 观察到的问题：
- 候选改进：
- 证据/案例：
- 是否只对个人有效：
- 下一步：观察 / 验证 / 建回归测试 / 提 PR
```

如果不能写本地文件，只在当前任务结束时指出值得记录的成长候选，不假装已经保存。

## Upstream Skill 处理

对于从上游 Fork 保留的 Skill（如 `life-decision-guide`）：

- 默认不直接修改原 Skill 文件，以降低和 upstream 同步时的冲突；
- 本成长协议通过仓库级 `AGENTS.md` 对其生效；
- 如果确实需要改变其方法论，先判断是：
  1. 应向 upstream 提交改进；
  2. 还是只在本 Fork 做 overlay；
- Fork 专属个性化规则优先放在上层 Skill 或共享协议中。

## 成长的目标

成长不是让 Skill 越写越长，而是让它：

- 更少犯重复错误；
- 更准确识别边界；
- 更快找到关键输入；
- 更稳定产出可执行结果；
- 更少依赖临场发挥；
- 更容易被测试、复用和维护。

当新增规则的维护成本大于收益时，不升级。
