# Test Plan Design + State Machine Analysis — Regression Tests

这些案例来自真实工程场景的抽象版本，不包含公司、项目或敏感参数。

## Case 1 — 接触器外发测试需求

### 场景
需要向外部测试方提交一个直流接触器验证需求，覆盖额定工况、重复冲击和高短路电流场景。

### 应触发
- `test-plan-design`
- `evidence-verification`
- `closed-loop-task-control`

### 期望
- 先定义验证命题；
- 区分额定寿命、冲击寿命、极限分断；
- 明确电压、电流、时间常数、循环/次数、环境与初始条件；
- 明确电压/电流/温度/辅助触点等采集量；
- 对高速分断波形给出采样/带宽要求的“需要定义”，而不是擅自编具体数值；
- 定义 Pass / Fail / Invalid Test；
- 明确粘连、喷弧、拒动、壳体损伤等失效记录；
- 测试完成后可回答原验证命题。

### 不应发生
- 只列“温升、寿命、短路”三个测试项目；
- 没有采集要求和判据；
- 因缺参数而自行创造参数。

## Case 2 — 预充状态机

### 场景
储能电池侧上电后，需要先预充 DC-link，再闭合主接触器进入正常运行。

### 应触发
- `state-machine-analysis`
- `system-modeling`
- `feedback-loop-analysis`

### 期望
至少识别：
- OFF / STANDBY；
- PRECHARGE；
- READY / CLOSE COMMAND；
- RUN；
- FAULT / SHUTDOWN。

并对 PRECHARGE → RUN 路径检查：
- 进入条件；
- 预充动作；
- 母线电压/压差观测；
- 阈值条件；
- 主接触器闭合命令；
- 辅助触点或其他反馈；
- 超时；
- 拒动；
- 粘连；
- 电压不上升；
- 故障后的恢复或锁止条件。

### 不应发生
- 把“闭合接触器”本身机械地当作所有场景下的独立稳定状态；
- 把“命令已发”当作“动作已完成”；
- 把预充解释成给电池充电；
- 对未知阈值和超时值脑补。

## Case 3 — 状态机转测试用例

### 场景
已有 PRECHARGE 状态机，需要设计测试用例验证控制逻辑。

### 应同时触发
- `state-machine-analysis`
- `test-plan-design`

### 期望
从每个关键转换派生至少：
- 正常转换测试；
- 边界阈值测试；
- 超时测试；
- 传感器/反馈异常测试；
- 拒动或粘连等故障测试。

每个用例都应包含：
- 前置状态；
- 输入/激励；
- 预期命令；
- 预期反馈；
- 转换结果；
- 时间要求（若受控文件给出）；
- 原始证据。

### 不应发生
- 状态图和测试用例彼此脱节；
- 只验证正常路径；
- 未知参数被擅自具体化。

## 通过标准

1. 两个 Skill 能互补而不是互相替代；
2. test-plan-design 负责“如何验证”；
3. state-machine-analysis 负责“系统如何按状态和条件演化”；
4. 二者都不越过证据边界；
5. 能从状态转换稳定地产生可验证测试用例。
