# Core Engineering Thinking Skills — Regression Tests

这些案例来自真实工程任务的抽象版本，只保留可复用结构，不包含具体公司、项目或敏感参数。

## Case 1 — DC 接触器验证需求

### 场景
一个直流接触器规格书给出了额定参数和部分分断能力。实际系统还存在额定工况、重复冲击工况和高短路电流工况，需要判断现有资料是否足够，以及测试需求如何补齐。

### 应触发
- `system-modeling`
- `evidence-verification`
- `closed-loop-task-control`
- 必要时 `feedback-loop-analysis`

### 期望行为
1. 先说明接触器在系统中的功能与失效后果，而不是直接抄规格书。
2. 区分：
   - 规格书能力；
   - 厂家历史测试报告；
   - 当前型号/版本/工况的实际验证。
3. 不把“额定能力满足”直接推导成“实际寿命满足”。
4. 将测试需求落到：
   - 工况；
   - 电压/电流；
   - 动作时序；
   - 测量量；
   - 采样；
   - 判据；
   - 失效模式；
   - 原始数据和波形；
   - 归档。
5. 如果需求仍缺少测试顺序、采样要求或判据，明确指出缺口。

### 不应发生
- 只说“规格书支持，因此可以使用”；
- 只列测试项目名称，没有可执行条件；
- 擅自补不存在的供应商数据。

## Case 2 — 熔断器选型与供应商回复核验

### 场景
供应商给出最小分断电流、最大短路能力、时间常数、温升与冲击寿命判据。工程师需要判断这些信息能否支持当前系统选型和验证。

### 应触发
- `evidence-verification`
- `system-modeling`
- `closed-loop-task-control`

### 期望行为
1. 先确认熔断器在保护链中的位置和保护对象。
2. 区分“产品参数存在”与“参数覆盖当前系统故障场景”。
3. 检查至少：
   - 额定电流与降额；
   - 最小分断；
   - 最大分断；
   - 时间常数；
   - I²t/保护协调；
   - 温升；
   - 冲击寿命；
   - 失效判据。
4. 对供应商文字回复标记证据强度；没有报告/曲线/实测数据时不得视为已验证。
5. 给出最小补证动作，而不是笼统说“继续问厂家”。

### 不应发生
- 把接触器的“可多次分断”逻辑套到熔断器；
- 忽略熔断器一次性动作属性；
- 把相近型号数据当当前型号结论。

## Case 3 — 电池控制箱与预充过程理解

### 场景
需要理解电池侧、保护器件、接触器、母线和外部功率变换设备之间的能量路径，以及预充过程到底在控制什么。

### 应触发
- `system-modeling`
- `feedback-loop-analysis`

### 期望行为
1. 先明确系统边界和主功率路径。
2. 分开画：
   - 能量链；
   - 控制链；
   - 状态反馈链。
3. 不把预充解释成“给电池充电”。
4. 明确预充本质是限制母线电容充电冲击，并使接触器两侧压差下降到允许闭合范围。
5. 检查预充前、预充中、主接触器闭合后的状态转换条件。
6. 未确认的端子/控制信号保持“待确认”。

### 不应发生
- 因为名称里有“充”就推断成电池充电；
- 只解释单个接触器，不解释状态顺序；
- 对未确认线束/端子关系进行脑补。

---

## Validation Result

### system-modeling
通过。三个案例都需要先恢复系统边界、主链路和模块关系，能显著减少局部思维。

### feedback-loop-analysis
基本通过。对于控制与状态反馈有效，但 Case 3 暴露出一个新能力缺口：**状态机/时序分析** 不应完全塞进反馈分析。

候选新 Skill：`state-machine-analysis`。

### closed-loop-task-control
通过。对于测试和供应商推进可以稳定补齐“验收”和“闭环证据”。

但 Case 1/2 也表明，测试设计本身应有更专业的独立 Skill，而不是全部放进任务闭环。

候选新 Skill：`test-plan-design`。

### evidence-verification
通过。尤其适合处理“规格书 ≠ 当前工况验证”“供应商文字回复 ≠ 一手证据”等工程场景。

## 结论

当前 4 个 Skill 可以进入主分支。

下一批优先级：
1. `test-plan-design`
2. `state-machine-analysis`
3. `requirement-clarification`
4. `component-selection`
