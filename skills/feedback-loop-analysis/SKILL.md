# Feedback Loop Analysis

## 核心问题

不是只问“发生了什么”，而是问：
**什么被测量 → 谁依据它做动作 → 动作如何改变系统 → 新状态又如何被测量。**

## 执行步骤

1. 找到被控制的目标量；
2. 找到测量/感知来源；
3. 找到决策器或控制器；
4. 找到执行动作；
5. 找到动作对系统状态的影响；
6. 找到反馈回路是否闭合；
7. 检查延迟、死区、饱和、阈值、噪声；
8. 检查是否存在相互冲突的多个回路；
9. 判断异常是：
   - 没有反馈；
   - 反馈错误；
   - 延迟太大；
   - 增益太强/太弱；
   - 执行器能力不足；
   - 判据设计错误；
   - 回路之间互相打架。

## 工程应用

例如接触器控制：
- 测量：电压/电流/状态量；
- 决策：BMS/BCMU 逻辑；
- 执行：线圈驱动；
- 结果：主回路开断；
- 反馈：辅助触点/电压状态/电流状态。

如果只看“线圈有没有电”，可能漏掉整个闭环。

## 输出

- 目标量；
- 感知；
- 控制逻辑；
- 执行动作；
- 反馈；
- 延迟/阈值；
- 可能的失稳或异常点；
- 建议验证项。

## 边界

不要把“反馈”只理解成自动控制。测试、供应商沟通、项目推进也存在反馈闭环。
