# System Modeling

## 目标

把“复杂问题”还原成一个可操作的系统模型，避免只盯局部零件或单点现象。

## 什么时候触发

- 需要理解一个复杂产品、系统或流程；
- 一个局部异常可能由上游/下游引起；
- 需要解释某个器件、模块、角色为什么存在；
- 需要做架构、接口、保护、测试或责任边界分析。

## 执行步骤

1. **定义系统边界**：明确分析对象包含什么、不包含什么。
2. **列出关键对象**：器件、模块、人员、信号、能量、数据或流程节点。
3. **画连接关系**：谁向谁传递能量、信息、控制或责任。
4. **标记输入输出**：正常输入、异常输入、系统输出、失效输出。
5. **标记状态**：启动、运行、降额、故障、恢复等关键状态。
6. **识别约束**：电压、电流、温度、时序、标准、资源、责任边界。
7. **找关键路径**：真正决定结果的主能量链、主信息链或主责任链。
8. **验证模型**：用一个正常场景和一个异常场景走一遍。

## 输出

优先输出：
- 系统边界；
- 关键对象；
- 主链路；
- 关键接口；
- 关键状态；
- 风险点；
- 还缺什么信息。

## 工程场景示例

对于储能主控箱，不要只问“接触器为什么断不开”，而先建模：
电池 → 熔断器 → 电流检测 → 接触器 → 断路器 → DC 母线 → PCS/负载，
再叠加 BCMU/BMS 控制链和保护链。

## 边界

- 这是分析模型，不等于真实物理系统；
- 未确认的连接、端子、控制逻辑必须标“待确认”；
- 不用复杂图形掩盖事实缺口。
