# Professional Interaction Capability Stack

This directory-level design treats books as evidence inputs, not as one-book-one-skill outputs.

## Capability modules

### workplace-transition
Primary source: Michael Watkins, *The First 90 Days*.
Use for:
- role transition
- manager alignment
- accelerated learning
- early wins
- stakeholder mapping
- transition risk control

### workplace-communication
Primary source: *Crucial Conversations*.
Use for:
- high-stakes conversations
- disagreement
- raising risks
- correcting misunderstandings
- restoring dialogue
- turning dialogue into action

### negotiation
Primary source: Fisher, Ury, Patton, *Getting to Yes*.
Use for:
- supplier negotiation
- resource negotiation
- scope/schedule tradeoffs
- salary/offer negotiation
- conflicting interests
- BATNA and objective-criteria analysis

## Routing logic
1. If the main problem is adapting to a role or manager -> workplace-transition.
2. If the main problem is how to have a difficult conversation -> workplace-communication.
3. If the main problem is allocating value, resources, scope, terms, or concessions -> negotiation.
4. If two or more apply, combine them in this order:
   - stabilize dialogue first
   - clarify interests and constraints
   - negotiate options/criteria
   - close ownership and next steps

## Evidence hierarchy
Books provide reusable behavior frameworks, not authoritative answers for technical, legal, financial, medical, or compliance facts.

For consequential decisions:
1. user/project facts
2. primary documents and official requirements
3. domain standards or authoritative sources
4. capability skill framework
5. recommendation and execution wording

## Validation rule
A skill should remain a draft until tested against real cases. Each real case should record:
- situation
- recommendation
- result
- what worked
- what failed
- rule to keep/change

Promote a draft to stable only after repeated real-world validation.
